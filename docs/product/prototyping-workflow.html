Disposable prototyping workflow

This workflow evaluates product design in the real Expo architecture without changing the implementation branch or production data.

  1. Create prototype/<feature-slug> from a clean, current main and add a worktree under /tmp/fieldsolo-prototypes/<feature-slug>.
  2. Reuse real navigation, tokens, and components. Put branch-only data behind fixtures or mock adapters; production writes must be disabled.
  3. Compare alternatives on Expo Web and a physical phone. Record the exact viewport/device and test scenario.
  4. Copy finalists into Figma page 08 Experiments as new nodes named YYYY-MM-DD / feature-slug / variant.
  5. Move the label from Exploring to Finalist, Approved, or Rejected. Never move or edit archive content.
  6. Record the decision in docs/product/decisions/ using the template.
  7. Remove the disposable worktree and branch after the decision is safely recorded.
  8. Implement the winner afresh from the decision note and maintained Figma node; do not merge prototype shortcuts.

Worktree commands

git fetch origin
git worktree add -b prototype/<feature-slug> /tmp/fieldsolo-prototypes/<feature-slug> origin/main

# compare variants, then record the decision

git worktree remove /tmp/fieldsolo-prototypes/<feature-slug>
git branch -d prototype/<feature-slug>

Prototype safety gates

  • No production credentials, write-capable adapters, migrations, or analytics emission.
  • Fixtures are obviously labeled and live only on the prototype branch.
  • Approval means design approval, not shipped functionality.
  • Figma Make is optional for unconstrained web concepts; it is not the Expo implementation baseline.
